# 要件定義書 — 脱炭素ニュースポータル（NewsPortal-DEC）

最終更新: 2026-07-10 / 対象リポジトリ: `shinjiro-watanabe-alt/newsportal-dec`

このドキュメントは、本プロジェクトを初めて引き継ぐ開発者（別セッションのAIエージェントを含む）が、
要件定義書・実装計画・テスト仕様書の3点セットのうちの1点として、まずここを読めば「何を作っているか」
「誰のために何を満たすべきか」を把握できることを目的に書かれている。

---

## 1. プロジェクト概要

### 1.1 これは何か

日本国内の脱炭素・カーボンニュートラル・水素・再生可能エネルギーに関する公開ニュース・行政情報を
自動収集し、GitHub Pages上で公開する**個人運営の静的ニュースポータルサイト**。

- サイト名: 「脱炭素ニュースポータル」（英語表記: ZEROCARBON JAPAN）
- 運営: 個人（S. Watanabe名義でフッターに表記）
- 公開URL: `https://shinjiro-watanabe-alt.github.io/NewsPortal-DEC/`（GitHub Pages、Source=GitHub Actions）
- バックエンドサーバー・データベースは存在しない。**ビルドステップなしの純粋な静的HTML/CSS/JS** +
  GitHub Actionsによる定期データ収集、という構成で完結する。

### 1.2 目的・提供価値

- 環境省・経済産業省・資源エネルギー庁・NEDO等の官公庁一次情報と、PR TIMES等の企業発表、
  一般ニュースサイトの脱炭素関連記事を横断的に集約し、毎日追わなくても最新動向を把握できるようにする。
- 単なるニュース一覧に留めず、CO2排出量・再エネ比率・ゼロカーボンシティ宣言状況などの統計値を
  ダッシュボードとして可視化し、**地方公共団体職員など政策・実務に関わる読者**が実務上参照しやすい形にする
  （具体例: 「本日の官公庁新着」「政策スケジュール」「公募中の補助金一覧」をまとめた
  『脱炭素行政ダイジェスト』ブロック）。
- 用語集により、専門用語のハードルを下げる。

### 1.3 想定利用者

- 一般個人（脱炭素・エネルギー政策に関心のある読者）
- **地方公共団体（都道府県・市区町村）の職員**: 脱炭素行政ダイジェスト（本日の官公庁新着、政策スケジュール、
  公募中の補助金一覧）は、この層の実務上のニーズを想定して設計されている。
- スマートフォン・PC双方からのアクセスを想定（`mobile.html`と`index.html`でレイアウトを分けている）。

## 2. 機能要件

### 2.1 画面一覧

| ファイル | 役割 | 備考 |
|---|---|---|
| `site/index.html` | PC版トップページ | 新着ニュース(トピックス)＋KPIストリップ＋技術キーワード絞り込み＋ニュース一覧＋右レール |
| `site/mobile.html` | スマホ版トップページ | index.htmlと同じデータを縦1カラムで表示。下部固定タブバーあり |
| `site/news.html` | ニュース一覧ページ | index.htmlからKPI・右レールを除いた、ニュースに特化した版 |
| `site/dashboard.html` | データダッシュボード | KPI4枚＋SVGグラフ6種＋都道府県別タイルグリッドマップ2種 |
| `site/glossary.html` | 用語集ページ | アコーディオン形式の用語一覧＋未登録候補件数表示 |
| `site/article.html` | 記事詳細ページ | `?id=`パラメータで`articles.json`から記事を特定して表示（ブックマーク・共有・印刷機能あり） |

いずれのページも `partials/*.html`（ヘッダー・フッター・右レール等の共通ブロック）を
`data-include`属性経由でfetchし、`site/data/*.json`をfetchして描画する（サーバーサイドレンダリング無し）。

### 2.2 主要機能

#### (A) ニュース収集・一覧表示
- 収集対象: 官公庁RSS/Atomフィード、環境省HTML一覧ページ、Googleニュース検索RSS（キーワード検索）。
  収集元一覧は `collector/sources.json` に外部化されている。
- 収集記事は脱炭素・水素・再エネ関連キーワード（`collect.py`の`KEYWORDS`）にマッチしたもののみ採用。
- カテゴリ自動分類（技術/自治体/国際/暮らし/企業/国/先行地域/その他の8分類、`categories.json`）。
- タブ切り替え（総合＋カテゴリ別）、カテゴリ別サイドナビ、技術キーワードショートカット、フリーワード検索、
  タグ検索（`?tag=`）、当日フィルタ（`?date=today`）に対応。
- 「もっと読み込む」によるページング表示。
- 記事にはOGP画像（取得できない場合はカテゴリ別のフォールバック画像/アイコン）を表示。

#### (B) データダッシュボード（`dashboard.html`）
- KPI4枚: 国内CO2排出量、電源の再エネ比率、カーボンプライス、ゼロカーボン宣言自治体数。
- SVGグラフ（自前実装、外部チャートライブラリ不使用）: CO2排出量推移（棒）、再エネ比率推移（折れ線）、
  カーボンプライス推移（折れ線）、ゼロカーボンシティ宣言状況・地域別（横棒）、部門別CO2排出量（横棒）。
- 47都道府県タイルグリッド地図（カートグラム）: ゼロカーボンシティ宣言状況（都道府県別）、
  再エネ導入比率（都道府県別、発電量を対数スケールのバーで併記）。
- 各グラフに参照元・基準日を表示（`charts`メタデータ）。
- ページ冒頭に「AIによるデータ収集結果に基づく統計が含まれるため、参考値としてご覧ください」の注記。
- 一部KPI・グラフは実データ連携済み（`live: true`）、一部は静的参考値（`is-static`表示バッジ）。

#### (C) 脱炭素行政ダイジェスト（右レール／`partials/rail.html`）
地方公共団体職員のニーズを想定した特化ブロック。以下3項目で構成:
1. 本日の新着（官公庁）件数 → クリックで `news.html?cat=national&date=today` へ
2. 政策スケジュール（直近4件、`schedule.json`）
3. 公募中の補助金一覧（`subsidies.json`、環境省・NEDO・経産省から自動収集）

#### (D) 用語集（`glossary.html` / 右レール簡易版）
- 手動管理の用語集（`glossary.json`）をアコーディオン表示。
- 話題のキーワードのうち用語集未登録のものを自動収集し（`glossary_pending.json`）、
  用語集ページ本編にのみ「未登録: N件」と件数表示（定義文の自動生成はしない。人手での確認・登録が前提）。

#### (E) 記事詳細（`article.html`）
- ブックマーク（localStorage）、共有（Web Share API、非対応時はクリップボードコピー）、印刷（`window.print()`）。
- 関連記事表示（`article.related`、現状は自動収集記事では空配列）。

#### (F) 表示設定（全ページ共通、`settings.js`）
- テーマ（ライト/ダーク）、記事サムネイルスタイル（写真風/アイコン風）、文字サイズ（小/標準/大）、
  ブランドカラー（6色から選択）を設定可能。
- 設定は `localStorage`（キー: `dn-settings`）に保存され、次回アクセス時も復元される。
  初期値（文字サイズ含む）は常に「標準」。

#### (G) レスポンシブ・モバイル最適化
- 820px以下でタイルグリッド地図・SVGグラフをタップで拡大モーダル表示（`DN.enableTapToZoom`）。
- CSS Gridは `minmax(0,1fr)` を用いてモバイル幅でのはみ出し（overflow）を防止。

### 2.3 非機能要件

- **静的サイトのみで完結**: ビルドツール・フレームワーク・バックエンドAPIを使わない。
- **自動更新**: GitHub Actionsが3時間ごとに収集スクリプトを実行し、変更があれば自動コミット・
  GitHub Pagesへ自動デプロイ。人手を介さず常に最新状態を保つ。
- **収集失敗時のフォールバック**: 外部データ取得（PDF解析・Excel解析・スクレイピング等）が失敗しても、
  既存データを保持しエラーにしない（cronベースの定期実行を止めないため）。
- **日本語UI**: 表示文言・エラーメッセージ等はすべて日本語。
- **アクセシビリティ**: `skip-link`、`aria-*`属性、`alt`属性など基本的な配慮を実装済み。
- **公開リポジトリ運用**: 機密情報・個人情報を含まない。外部への意図しないデータ送信を行わない
  （収集は公開RSS/検索RSS/官公庁公開ページの読み取りのみ）。

## 3. データ要件

すべて `site/data/*.json` に集約される。**「収集スクリプトが自動生成・上書きするデータ」**と
**「手動管理の静的データ」**に分かれる（後述の実装計画にも詳細あり）。

### 3.1 自動生成データ（`collector/collect.py`が毎回上書き）

| ファイル | 内容 |
|---|---|
| `articles.json` | 収集記事の全件（辞書、キー=記事ID）。最大1,000件保持 |
| `feed.json` | 直近30件の簡易フィード表示用 |
| `categories.json` | カテゴリ一覧＋各カテゴリの記事件数 |
| `topics.json` | トップ記事（lead）＋見出しリスト（headlines、最大8件） |
| `ranks.json` | 話題のキーワードランキング（上位8件、トレンド判定付き） |
| `events.json` | イベント・セミナー情報（開催日を過ぎたものは自動除外） |
| `meta.json` | 最終更新日時（`updated_at`）。画面上の「更新日時」表示はすべてここを参照する |
| `subsidies.json` | 環境省・NEDO・経産省の公募中案件一覧 |
| `glossary_pending.json` | 話題のキーワードのうち用語集未登録の候補（人手登録待ち） |
| `renewable-by-prefecture.json` | 都道府県別再エネ導入比率・発電量（週1回更新） |
| `kpis.json`（一部フィールドのみ） | 「ゼロカーボン宣言」KPIの値のみ実データ更新（他は静的） |
| `dashboard.json`（一部フィールドのみ） | ゼロカーボン宣言関連KPI・都道府県別宣言状況のみ実データ更新 |
| `rail-data.json`（一部フィールドのみ） | 「卸電力価格」のみJEPXの実データで更新 |

### 3.2 手動管理データ（収集スクリプトは触らない）

| ファイル | 内容 |
|---|---|
| `glossary.json` | 用語集本体（term/definition） |
| `shortcuts.json` | 技術キーワードショートカット（アイコン・ラベル・タグ） |
| `schedule.json` | 政策スケジュール（日付・タイトル・種別・URL） |
| `dashboard.json`（大部分） | CO2排出量推移・再エネ比率推移・カーボンプライス推移・地域別ゼロカーボン・
  部門別CO2排出量等の静的参考値（`charts`メタの参照元表記含む） |
| `kpis.json`（大部分） | CO2排出量・再エネ比率・カーボンプライスKPI（静的参考値） |
| `rail-data.json`（一部） | 電力需給ピーク率・太陽光出力制御（静的参考値） |

どちらに属するかは `.github/workflows/collect-decarbon-news.yml` の `git add` 対象リスト
（後述）が実質的な正とみなせる。

### 3.3 データソース一覧（対外部データ取得先）

| 用途 | 取得先 | 頻度 |
|---|---|---|
| ニュース記事 | 環境省・経産省・資源エネルギー庁・NEDO・JOGMEC・PR TIMES・ITmedia・はてなブックマーク（RSS/Atom）＋Googleニュース検索RSS | 3時間毎 |
| ゼロカーボンシティ宣言自治体数（総数・都道府県別） | 環境省サイト（HTML本文 or リンク先PDF解析） | 週1回に間引き |
| 都道府県別再エネ導入比率・発電量 | 資源エネルギー庁「電力調査統計」Excelファイル（直リンクURL固定） | 週1回に間引き |
| 卸電力価格（スポット平均） | JEPX（日本卸電力取引所）CSV | 3時間毎 |
| 公募中の補助金・公募情報 | 環境省・NEDO・経済産業省の公募ページ（HTMLスクレイピング） | 3時間毎 |

## 4. 制約条件

### 4.1 リポジトリ運用ルール（`CLAUDE.md`より、開発時に厳守）

- 既存ファイルの更新・コミットは無断で行わず、必ず事前にユーザーへ確認する。
- 指示に関係のないファイルは編集しない。指示範囲を超えた追加修正・リファクタリングはしない。
- 既存ファイルの削除は禁止（本ドキュメント作成時点でも遵守）。
- 破壊的Git操作（force push、`reset --hard`、ブランチ削除、他者コミットのamend/rebase等）は
  明示的な許可がある場合を除き禁止。
- PRのマージは「マージコミット」方式に統一（squash/rebase不可。作業ブランチを使い回す運用のため、
  squashだと次回以降のPRで`add/add`コンフリクトが起きやすくなる）。
- `.env`系の機密ファイルは自動で読み取らない。
- 外部送信（メール・チャット投稿・本リポジトリ以外のGitHub操作等）は原則禁止。
  公開されたRSS/検索RSS等へのアクセス（読み取り）のみ許可。
- 判断に迷う場合は推測で進めず、ユーザーに確認する。

### 4.2 技術的制約

- **開発サンドボックス環境から外部サイトへ到達できない**（ローカルでのcollect.py動作確認は限定的）。
  実際のネットワークアクセスを伴う検証はGitHub Actions上で行う必要がある
  （`collector/explore_feeds.py`は診断専用でこの目的のために作られている）。
- 収集スクリプトはPython標準ライブラリのみで完結する設計方針だが、PDF解析（`pypdf`）・Excel解析
  （`openpyxl`）のみ例外的に外部パッケージを利用（`collect-decarbon-news.yml`でpip install）。
- Google Fonts（Material Symbols Outlined含む）を利用しているため、外部フォントに到達できない
  検証環境ではアイコンがテキスト表示になる（例: `zoom_in`という文字列がそのまま出る）。
  これは既知の環境依存の見た目の差異であり、本番環境（GitHub Pages）では問題にならない。

## 5. 用語集（開発用語）

| 用語 | 意味 |
|---|---|
| パーシャル (partial) | `site/partials/*.html`。ヘッダー・フッター・右レール等の共通HTML断片。`data-include`で差し込む |
| `dn:partials-loaded` | 全パーシャルの差し込み完了後に発火するカスタムイベント。データ描画系JSはこれをトリガーに動く |
| DN | `site/assets/js/data.js` で定義されるグローバルヘルパー名前空間（`DN.fetchJSON`、`DN.esc`等） |
| 引き継ぎ記事 | `collect.py`が前回の`articles.json`から`collected: true`のものだけを次回実行に持ち越す仕組み |
| デデュープ (dedupe) | 複数の収集元から同じ記事が別IDで重複登録された場合に、正規化タイトルを基準に1件へ統合する処理 |
| 間引き収集 | ゼロカーボンシティ宣言数・再エネ導入比率など、日次では変動しないデータを週1回だけ収集する仕組み |
